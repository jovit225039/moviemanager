# ReelPlan — Movie Watchlist Manager

A MERN-stack movie planning app built for the Full Stack Development exit examination.

## Stack
- React + Vite
- Express.js
- Node.js
- MongoDB Atlas
- Mongoose
- Vercel (frontend)
- Render (backend)

## Project structure
```text
movie-watchlist-manager/
├── frontend/
├── backend/
├── .gitignore
└── README.md
```

## API list

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/movies` | Add a movie |
| GET | `/api/movies` | List, search, filter and paginate movies |
| GET | `/api/movies/next` | Return the best movie to watch next |
| GET | `/api/movies/stats` | Dashboard statistics |
| GET | `/api/movies/:id` | Get one movie |
| PUT | `/api/movies/:id` | Edit allowed movie fields |
| PATCH | `/api/movies/:id/status` | Move through the status workflow |
| DELETE | `/api/movies/:id` | Delete a movie when allowed |
| GET | `/api/health` | Backend health check |

### Movie list query parameters

`GET /api/movies?status=To%20Watch&genre=Drama&search=dark&page=1`

The API returns six movies per page and includes `totalPages`.

## Environment variables

Backend `.env`:
```env
PORT=5000
MONGODB_URI=YOUR_MONGODB_ATLAS_TEST_URI
CLIENT_URL=http://localhost:5173
```

Frontend `.env`:
```env
VITE_API_BASE_URL=http://localhost:5000/api
```

For Vercel, set `VITE_API_BASE_URL` to the deployed Render API URL followed by `/api`.

For Render, set `MONGODB_URI`, `CLIENT_URL`, and `PORT`.

> Use an exam/test MongoDB Atlas account or other dummy credentials. Never commit a personal production password.

## Validation implemented

- Release year: 1950 through the current year.
- Runtime: 30–300 minutes.
- Duplicate title + release year is case-insensitive and returns HTTP 409.
- Movie code is generated by the backend as `MV-<year>-<3 digits>`.
- Status transitions are enforced by the backend.
- Rating is accepted only for Watched movies and is mandatory when moving to Watched.
- Watched Date is generated by the backend.
- Watching movies cannot be deleted.
- Watch Next uses highest priority, then shortest runtime.
- Statistics are calculated by the backend and refreshed after mutations.
